## Known Limitations

- **Remote R2 still BLOCKED:** `wrangler r2 bucket list/create` → `Please enable R2 [10042]` on account `8b3bb123...` — requires dashboard `https://dash.cloudflare.com/8b3bb12337230057867f31aa509835e4/r2/overview` → `Enable R2`. Until enabled, `POST /api/photos/upload` correctly returns `503 R2 storage not configured` (graceful, not crash) and `node scripts/optimize-upload.mjs --all-pending --remote` cannot run. `wrangler.toml` `[[r2_buckets]]` is now **commented out** with note to allow `pages deploy` to succeed; `env.R2` is `undefined` in production (handled via `if (!env.R2) 503`). Local `.wrangler/state/v3/r2` works via `--local`.
- **Media optimization still manual:** `scripts/optimize-upload.mjs --all-pending --remote` requires manual `node` run or CI `workflow_dispatch`/`cron`; no automatic Queue/Trigger. `sharp` correctly **not** in `functions/` (verified `grep -r sharp functions/` 0), but pending photos remain `processing_status='pending'` until manual run.
- **Static fallback still required:** `src/content/gallery` 75/300 remains as resilience; removal documented in `docs/cms-migration.md` step 8, but not yet removed (intentional until D1 has ≥6 categories + ≥50 photos verified in production for 1 week).
- **Custom R2 domain not configured:** `R2_PUBLIC_URL` not set in production (`pages secret list` shows only `JWT_SECRET`), so `image_url` fallback is `/${r2_key}` via `functions/api/media/[[path]].js` (works when R2 enabled, but not CDN-optimized). Production should set `https://images.muwanshots.com` via `wrangler pages secret put R2_PUBLIC_URL`.
- **Sitemap image entries not per-photo:** Only `url` entries for categories/albums, not 75 `image:image` per photo (intentionally to avoid 300-entry bloat, documented).
- **No per-photo `lastmod` in sitemap:** Uses category `updated_at` only.
