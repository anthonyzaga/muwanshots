- **Remote D1/R2 not provisioned:** `wrangler.toml` still `database_id = "00000000..."`, `wrangler d1 list` shows no `muwanshots-db`, `wrangler r2 bucket list` → `Please enable R2 [10042]`. Production Phase 3.1 media pipeline (pending → variants) cannot run remotely until `wrangler d1 create` + `r2 bucket create` + `wrangler pages secret put JWT_SECRET` are executed via dashboard and `wrangler.toml` updated. Local `.wrangler/state/v3/d1` works, but `muwanshots.pages.dev` 1-week-old deployment still serves static fallback, not D1 content.
- **Media optimization still manual:** `scripts/optimize-upload.mjs --all-pending --remote` requires manual `node` run or CI `workflow_dispatch`/`cron`; no automatic Queue/Trigger. `sharp` correctly **not** in `functions/` (verified `grep -r sharp functions/` 0), but pending photos remain `processing_status='pending'` until manual run.
- **Static fallback still required:** `src/content/gallery` 75/300 remains as resilience; removal documented in `docs/cms-migration.md` step 8, but not yet removed.
- **Custom R2 domain not configured:** `R2_PUBLIC_URL` empty in production (`pages secret list` empty), so `image_url` fallback is `/${r2_key}` via `functions/api/media/[[path]].js` (works but not CDN-optimized). Production should set `https://images.muwanshots.com` via `wrangler pages secret put R2_PUBLIC_URL`.
- **Sitemap image entries not per-photo:** Only `url` entries for categories/albums, not 75 `image:image` per photo (intentionally to avoid 300-entry bloat, documented).
- **No per-photo `lastmod` in sitemap:** Uses category `updated_at` only.
